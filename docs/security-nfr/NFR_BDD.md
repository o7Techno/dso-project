## Feature: Security NFR — Event Planner

  Scenario: Хранение паролей
    Given новый пользователь регистрируется
    When пароль сохраняется в базе
    Then он должен быть захеширован (не plain-text, Argon2id или bcrypt)

  Scenario: Ограниченный срок сессии
    Given пользователь вошёл в систему
    When прошло 31 минута
    Then сессия должна быть недействительна

  Scenario: Создание события в прошлом
    Given пользователь создаёт событие
    When дата события меньше текущей даты
    Then система возвращает 400 Bad Request

  Scenario: Доступ только к своим событиям
    Given два пользователя
    When пользователь A пробует получить событие пользователя B
    Then система возвращает 403 Forbidden

  #### Негативные сценарии
  Scenario: Внешний API зависает
    Given внешний календарный сервис не отвечает
    When приложение делает запрос
    Then оно должно завершить попытку ≤ 5 секунд и не делать больше 2 ретраев

  Scenario: Попытка создать дубликат события
    Given у пользователя уже есть событие с одинаковыми title, date и place
    When он создаёт новое с теми же параметрами
    Then система возвращает 409 Conflict
