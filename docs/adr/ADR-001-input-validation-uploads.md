# ADR-001: Валидация загрузок (magic bytes, лимиты размера, безопасность путей)

- **Статус:** Принято
- **Дата:** 2025-11-03

## Контекст
Пользователи загружают файлы (например, изображения событий или вложения). Полагаться на имя файла или заявленный MIME-тип небезопасно. Необходимо предотвратить path traversal, злоупотребление симлинками и загрузку чрезмерно больших файлов.

## Рассмотренные альтернативы

### 🔹 Альтернатива A — проверять только MIME-тип из заголовка
- **Плюсы:** просто реализовать, не требует чтения тела.
- **Минусы:** легко подделывается клиентом; не защищает от вредоносных файлов.
- **Вывод:** отклонено — слишком высокий риск обхода.

### 🔹 Альтернатива B — использовать внешнюю антивирусную службу
- **Плюсы:** повышает уверенность в чистоте содержимого.
- **Минусы:** высокая латентность, зависимость от стороннего сервиса, стоимость.
- **Вывод:** возможна интеграция в будущем, но не для MVP.

### 🔹 Альтернатива C — собственная проверка сигнатур (magic bytes) + лимиты
- **Плюсы:** высокая надёжность, независимость от клиента.
- **Минусы:** необходимость поддерживать таблицу сигнатур.
- **Вывод:** выбрана как баланс безопасности и простоты.

## Решение
- Проверка сигнатур (magic bytes) разрешённых типов: PNG, JPEG, PDF.
- Жёсткий лимит размера (1 MiB), запрет пустых файлов.
- Игнорирование имени файла от клиента, сохранение под UUID v4.
- Хранение только в каталоге `uploads/`; канонизация путей, запрет симлинков.

Реализовано в `app/main.py` эндпоинтом `POST /upload`:
- Проверка сигнатуры по заявленному `content_type`.
- Контроль размера с кодом ошибки 413 при превышении.
- Имена файлов — UUID; исходное имя игнорируется.
- Проверка канонического пути и отсутствие симлинков.

## Влияние на безопасность
- Уменьшает риск RCE/LFI и утечек PII.
- Снижает вероятность DoS при массовых загрузках.
- Потенциальный риск: ложные отказы при редких типах файлов (минимален).

## Меры смягчения
- Логирование отклонённых загрузок с ограничением чувствительных данных.
- Добавление MIME-типов по запросу через безопасный процесс ревью.

## Definition of Done
- Все проверки (размер, MIME, сигнатура, путь) реализованы и покрыты тестами.
- Все тесты `tests/test_uploads.py` зелёные.
- Код-ревью безопасности пройден.

## Rollout-план
1. Включить загрузки в тестовом окружении.
2. Проверить, что все поддерживаемые клиенты работают.
3. Включить в проде с мониторингом ошибок (Sentry).
4. Через 1 неделю пересмотреть лимиты и MIME-allowlist.
