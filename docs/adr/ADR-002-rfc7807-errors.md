# ADR-002: Ошибки в формате RFC 7807 (problem+json) с correlation_id

- **Статус:** Принято
- **Дата:** 2025-11-03

## Контекст
Непоследовательные форматы ошибок усложняют обработку на стороне клиента и могут раскрывать детали реализации. Требуется единообразный, безопасный и трассируемый формат ответов об ошибках.

## Рассмотренные альтернативы

### 🔹 Альтернатива A — собственный JSON-формат
- **Плюсы:** гибкость.
- **Минусы:** не стандарт; клиенты не могут переиспользовать существующие библиотеки.
- **Вывод:** отклонено — отсутствие совместимости и стандарта.

### 🔹 Альтернатива B — только HTTP-коды без тела
- **Плюсы:** минимализм.
- **Минусы:** теряется контекст ошибки, сложность диагностики.
- **Вывод:** отклонено — UX и диагностика страдают.

### 🔹 Альтернатива C — RFC 7807 (problem+json)
- **Плюсы:** стандарт; поддержка во многих фреймворках.
- **Минусы:** требует адаптации существующих исключений.
- **Вывод:** принято как наилучший вариант.

## Решение
- Принят RFC 7807 (problem+json) для всех прикладных ошибок.
- Добавлен `correlation_id` (UUID v4) для трассировки запросов.
- Маскирование внутренних деталей, карта `errors` для валидации.
- Реализовано middleware + обработчики исключений в `app/main.py`.

## Влияние на безопасность
- Исключает утечки внутренних стеков и конфиденциальных данных.
- Улучшает расследование инцидентов благодаря `correlation_id`.
- Повышает прозрачность, снижая риск дублирования логов.

## Меры смягчения
- Валидация формата ошибок в CI-тестах.
- Сканирование ответов на наличие стектрейсов или секретов.

## Definition of Done
- Все ошибки приложения возвращаются в формате RFC 7807.
- В логах и ответах всегда присутствует `correlation_id`.
- Все тесты `tests/test_errors.py` зелёные.

## Rollout-план
1. Включить middleware на stage-окружении.
2. Проверить совместимость с веб-клиентом.
3. Включить на production и отслеживать корреляцию в логах.
4. Через неделю провести анализ обратной совместимости.
